# 多租户身份与运营支持

本页说明身份接入、工作上下文、案件只读支援、租户预算与生命周期操作。服务端根据已验证身份和有效 membership 解析租户、组织、角色及授权范围。租户是身份与隔离边界，组织是租户内的组织单元；展示名称、ID、URL 或请求字段不能授予访问权。术语沿用 [`glossary/concepts.json`](../glossary/concepts.json) 的租户概念和本手册的多公司范围，不另建术语表。

本文依据固定 main `faeca3938293169f9d7d190b9e4c140feb85d8ae`。PR #146、#154、#155、#156 已合入，当前 schema 为 39。源码具备身份成员映射、上下文围栏、预算/费用账本和受限租户生命周期操作；目标环境的身份来源、白名单、部署和现场验收仍须单独确认。

## 身份接入与成员导入

企业模式从部署方提供的可信身份目录读取身份。目录读取或解析失败时，当前副本拒绝依赖该目录的授权；last-good revision 仅用于诊断，不能继续授权。目录更新传播时间取决于各服务副本和部署平台。

成员关系通过明确的 identity crosswalk 导入。授权方须显式列出 jurisdiction、tenant、org unit、principal 和 membership；principal 的稳定 actor ID、issuer、subject 必须与启用目录中同一身份匹配。不得从姓名、邮箱或调用方填写的租户/角色推断授权。导入使用独立 `cmd/identity-import`，先默认 dry-run，审阅输入摘要和变更后才由受控管理身份显式 `--apply`。输入和输出可能包含组织身份信息，应保存在受限仓外目录；不能使用 Core 运行凭据。

Crosswalk 仅用于新 tenant 初始化 status。既有 tenant 的 status 和 `live_epoch` 由生命周期操作管理。新建身份行不等于用户已完成登录、权限试用或生产接入验收。

## 工作上下文切换

只有服务端返回且用户确有有效 membership 的上下文可供选择。切换入口受 Core `CONTEXT_SWITCH_ENABLED` 门控，默认关闭；启用前需由授权管理员完成目标 schema 迁移、crosswalk 与权限审查。切换后服务端递增会话 context version，前端清除旧范围缓存并重新读取。写入还校验 CSRF、会话和上下文版本。

若操作返回上下文冲突，刷新会话和当前页面，核实租户与组织后重新填写操作。不要重放旧 context version、CSRF token，或通过 URL、请求体更改 tenant ID。切换上下文不会自动授予每个案件的访问权；每个请求仍由服务端判断。

## 案件级只读支援

案件支援只允许精确单案的 `case.read`。申请需指定受益 principal、案件、理由和到期时间；独立授权人批准后生效。授权可撤销并会到期，受益人仍用自己的企业身份登录。它不会切换租户或组织，也不能执行写操作、保存人工决定、签署、导出或写回外部系统。

如果身份、案件范围或授权状态无法确认，停止查看并联系租户管理员。不要共用账号、临时添加成员、扩大角色或通过导出文件转交合同内容。待批准、过期或已撤销的授权均不可使用。

## 预算、配置与运行开关

设置页运营面板显示当前会话租户的目录状态、租户状态与 live epoch、队列政策、模型网关容量快照、调用用量和日/月成本。预算网关未配置或不可用时，上限和余量显示未知；未知费用不等于零。最近 60 秒未报告用量的调用按服务端的保守预留规则处理；全局预算同时约束所有租户。最终受理以账本与网关实时结果为准，超额度调用会被拒绝。

具有相应租户管理员权限的用户可预览并采用允许的配置，也可独立停止或恢复后续模型发送。停止后服务端拒绝新的模型发送，已发调用仍按预留结算；恢复后仍需满足配置、授权和预算条件。这个按钮不暂停租户全部任务或证明外部模型服务已经连接。队列权重和上限用于描述调度配置，不表示 CPU 公平性或当前可用容量。

## 租户开通、停用与重新激活

租户开通/停用/重新激活是受限平台生命周期操作，不是普通租户管理员设置。执行者必须是 admin，且 actor ID 同时出现在 `CAW_PLATFORM_OPERATOR_ACTORS`，Core 实际 PostgreSQL login 同时出现在 `CAW_PLATFORM_OPERATOR_DATABASE_PRINCIPALS`。两项默认空；身份授权名单不能替代数据库 login 白名单。

操作按幂等键创建，并按服务端顺序处理身份、租户配置、运行就绪或用量对账步骤。每步保留 revision 与回执摘要。停用会先把租户置为 suspended 并递增 live epoch，再要求完成 usage reconciliation；未知费用 hold 未对账会阻止完成。重新激活要求有效辖区、启用的租户管理员成员关系、已有配置及指定版本。身份、配置或外部回执有冲突时，保存 operation ID，核对权威状态后再续办；不要盲目重试或直接改 SQL。

## 支持分批路径与异常处理

建议按权限和影响范围逐步提供支持：

1. 用户自查当前上下文、页面状态和中文错误提示；身份或上下文错误时刷新，不更换请求字段。
2. 本租户管理员处理有效成员关系、配置、预算快照和实时模型停发；未知费用或额度先按保守方式处理。
3. 需要查看具体案件时申请短时、单案件 `case.read` 支援，由独立授权人审批。
4. 跨租户开通、停用或重新激活由满足双白名单的平台运营者处理，并保存逐步回执。
5. 备份恢复或专属池切换转入[备份与恢复边界](tenant-restore.md)所列前置检查；状态切换不能代替租户数据抽取与恢复。

| 提示或情况 | 处理方式 |
| --- | --- |
| 身份目录不可用 | 停止依赖该目录的授权操作，联系管理员检查目录版本与副本更新。不要继续使用 last-good revision。 |
| 当前会话或上下文已变化 | 刷新会话和页面，核对租户/组织，再重新提交；不要重放旧请求。 |
| 当前身份未获平台租户控制授权 | 由平台管理员核对精确 actor ID 与 Core 数据库 login 两项白名单。普通租户管理员不会自动取得平台运营权。 |
| 租户操作状态或前置条件冲突 | 保留 operation ID 与 revision，核对服务端已完成步骤和外部回执后，再由授权运营者续办。 |
| 预算网关不可用或余量未知 | 不把未知视为无限额或零费用；核对服务端账本，必要时暂停新的模型发送。 |
| 支援授权待批准、到期或已撤销 | 停止读取案件，由独立授权人复核范围、理由和期限。 |
| 需要恢复租户数据 | 不通过停用/重新激活或上下文切换代替恢复；按恢复手册确认快照、对象、key、幂等和单写者前置条件。 |

源码功能不表示生产身份接入、真实预算配置、租户试用或恢复演练已完成。当前固定候选的实际部署、真实用户试用、生产恢复与完整 Phase 4 验收均为 **NOT_RUN**；缺少批准或目标环境材料时为 **BLOCKED**。
