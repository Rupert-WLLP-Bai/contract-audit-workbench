# 用户上手与扩展指南

本指南说明如何完成一次案件审查、如何通过现有规则包和只读连接器扩展能力，以及如何参与上游贡献。实际入口和权限以部署配置、当前账号及服务端返回为准。

- 第一次开发环境启动见[本地开发](local-development.md)。
- 产品能力与边界见[能力与边界](../product/capabilities.md)和[案件审查工作流](../product/workflow.md)。
- 贡献流程见[贡献与协作](contributing.md)，许可信息见[许可与贡献](licensing.md)和仓库根目录 [`LICENSE`](../../LICENSE)。

## 完成一次案件审查

以下步骤适用于已有相应账号和案件权限的用户。演示账号只用于本机开发和测试环境。

1. 登录部署方提供的工作台，打开“案件管理”。有权创建案件的账号选择“新建案件”，填写标题并选择当前已发布且适用的业务线、场景和合同类型。案件编号和授权范围由服务端创建；不要自行构造租户或组织编号。
2. 打开案件，在材料区域选择“新增材料”，上传获准用于该案件的合同材料，并按业务用途选择材料角色。等待解析完成。新材料不会自动加入已开始的审查。
3. 查看“审查准备”和“下一步”，按服务端列出的缺项补材料、确认本次材料集合或修正业务时间。若准备状态或权限未知，先联系管理员，不要绕过提示。
4. 选择“开始审查”或“开始复审”。系统冻结本次使用的材料、规则和知识版本。配置变化后应发起新审查；旧尝试、人工决定和报告不会被新结果覆盖。
5. 在“审查工作区”核对每条线索引用的冻结原文、定位和依据，再提交人工判断。模型输出是建议，不是审批。无法核验引用时，不要把建议记为已确认事实。人工决定须填写理由并追加保存。
6. 按服务端提示生成报告。报告绑定所选审查记录；生成后不会随材料变化。归档需要相应权限和服务端要求的报告，不会删除案件历史。

只读账号不能代替经办人上传材料或代替审查员保存决定。跨组织、跨租户案件访问须由服务端正式授权；浏览器显示的名称、链接或导出文件本身不构成授权。

## 多租户用户与运营操作

租户是身份与数据隔离范围；组织、成员关系和租户不是可互换的编号。服务端从已验证身份与有效 membership 解析当前请求范围。请从页面提供的成员关系中选择工作上下文；手改 tenant ID、组织 ID、URL 或请求字段不会授予访问权。旧页面或命令遇到上下文版本冲突时，刷新会话与页面后重新确认成员关系，再重新填写操作。术语沿用 [`glossary/concepts.json`](../glossary/concepts.json) 中的租户与上下文概念。

新租户接入由授权方准备明确的 jurisdiction、tenant、org unit、principal 和 membership crosswalk。先在受限目录审阅文件，再以离线管理身份运行 `identity-import` 默认 dry-run；核对摘要和目标库后才可按审批显式 `--apply`。不要从姓名、邮箱或角色字段猜测身份。Crosswalk 只初始化新 tenant 的状态；已有 tenant 的 status 和 live epoch 必须经生命周期操作改变。导入结果不证明用户已完成首次登录或目标环境已验收。

案件只读支援限定一个案件和 `case.read`。申请人提交准确人员、案件、理由和到期时间，由独立授权人批准；支援授权可撤销并到期。受益人以自己的企业账号登录。该授权不能代替成员关系，也不能审查、写决定、签署、导出或写回外部系统。申请被拒或授权到期时，停止支援并由案件所属租户管理员确认后续路径。

设置页的运营面板显示当前租户的身份目录状态、租户状态与 epoch、队列政策、模型网关容量快照、调用用量及日/月成本。未知上限或用量保持“未知”，不得按零处理。租户管理员可按当前配置权限预览/采用配置，并独立停止或恢复后续模型发送；停止后已发出的调用仍按预留结算，恢复后新调用仍受实时授权、租户配置和预算账本约束。该开关不代表暂停全部租户任务。

租户开通、停用或重新激活属于平台运营流程。操作须同时匹配 `CAW_PLATFORM_OPERATOR_ACTORS` 中的精确 actor ID 与 `CAW_PLATFORM_OPERATOR_DATABASE_PRINCIPALS` 中 Core 实际数据库 login；普通租户管理员不会自动成为平台运营者。操作按幂等键创建，并逐步核对身份、配置、运行就绪或用量对账回执。步骤遇到外部结果未知或 revision 冲突时，不要盲目重试；保留 operation ID，先核对外部事实，再由授权平台运营者按服务端 reconciliation 路径续办。

建议分批提供支持：先由用户自查页面状态与中文错误提示；再由本租户管理员核对身份、配置、预算和实时停发；需要案件内容时申请短时 `case.read` 支援；跨租户开停或重新激活只交给经过双白名单授权的平台运营者；数据恢复单独进入经批准的恢复流程。每一批都只覆盖已验证的账号、租户和场景，不把源码存在当作环境验收。

### 常见提示

| 界面提示 | 处理方式 |
| --- | --- |
| 当前账号没有发起审查权限 | 请由具备权限的经办人、审查员或管理员处理；不要修改客户端身份或请求字段。 |
| 材料集合待确认或解析失败 | 按准备清单检查材料、解析状态和本次选择；失败材料仍保留在案件中，不代表风险为零。 |
| 无法确认是否可以开始审查 | 刷新服务端准备清单。状态仍未知时联系管理员，不要把未知当作可执行。 |
| 请修正以下字段 | 在规则包编辑页按字段提示修改草稿，再运行服务端校验。 |
| 本次运行没有形成风险线索 | 这不等于合同无风险，也不代替人工复核。 |
| 登录、材料读取或保存失败 | 记录案件编号和页面错误并联系管理员。不要在公开 Issue、截图或日志中附合同原文、凭据或个人信息。 |
| 当前会话或上下文已变化 | 重新登录或刷新页面，核对当前租户和组织，再重新提交；不要重放旧请求。 |
| 当前身份未获平台租户控制授权 | 请平台管理员核对精确 actor ID 与 Core 数据库 login 双白名单。租户管理员权限不会自动获得平台运营权。 |
| 租户操作当前状态或前置条件不允许此步骤 | 保留 operation ID 和 revision，先核对当前状态及已完成步骤，再联系授权平台运营者续办。 |
| 暂时无法读取预算上限或余量 | 保持未知；暂停需要精确预算判断的调用，并由管理员核对模型网关与服务端账本。 |

## 现有扩展方式

### 规则包

有对应管理权限的管理员可在“规则包治理”创建草稿、填写规则范围和依据并运行服务端校验。若清单包含 fixture suite，再运行对应用例，然后按治理步骤批准并发布。页面只接受当前会话所属的可信租户；输入中的 tenant ID 不是授权来源。

规则阈值使用十进制或规范有理数表示，避免浮点舍入。每条规则应声明业务范围、比较器、事实维度、材料角色、单位、所需对象和依据来源。样例 [`author-demo.json`](../../internal/rulepack/testdata/author-demo.json) 是合成数据，只用于理解 `rulepack/v1` 字段，不是合同或政策依据。

发布后，审查受理会冻结规则包版本和摘要。修改已发布规则应建立新版本；不得覆盖旧审查或伪造旧版本批准。校验失败时按页面字段提示修正后再提交。

### 能力包

Capability pack 是受限 JSON 清单，声明业务场景、材料角色、精确 RulePack 版本、能力和比较器引用、显示字段及 fixture 标识。主机只接受预先登记的 capability、connector 和 comparator；未知引用、重复版本或不支持的 host contract 会被拒绝。

服务从源码嵌入已审查清单并与主机白名单比对。系统不提供用户上传 ZIP、网络安装包、运行包内脚本或 SQL、第三方动态插件发现，或任意比较器。新增能力清单需提交上游评审，并同时核对主机实现、白名单、fixture 和授权边界；只添加 JSON 不代表功能已经上线。

### 外部只读连接器

Go 接口合同见 [`internal/auditext/types.go`](../../internal/auditext/types.go)。`ReadConnector` 只提供 `ID()` 和 `Read(context.Context, ReadRequest) (Observation, error)`。服务端构造授权范围、映射和对象标识；调用方不能提供任意 URL、HTTP 方法、请求头或凭据。Observation 应带版本、时间范围、可用性和证据字段。外部快照证据与合同原文引用是不同类型。

该接口位于 Go `internal/` 路径，不是独立 Go module 可导入的稳定 SDK。连接器由宿主服务实现，部署方固定 endpoint、凭据、白名单、超时和响应大小。工具与外部业务读取保持只读；新增连接器不能增加外部写回、自动审批、签署或付款。真实来源接入须有授权、配置和实际读取证据。

### HTTP API 与类型变更

HTTP 契约以 Go 中的类型与路由声明为源。`make generate-openapi` 先运行 Go OpenAPI 生成器，再生成前端 TypeScript wire 类型；`make check-openapi-generated` 检查两者是否与源码一致。新增或修改路由、DTO、状态或错误码时，先更新 Go 契约，再运行生成与受影响检查。不要手改 `internal/apidocs/openapi.json` 或 `web/src/api/wire.generated.ts`，也不要把数据库字段名当作外部 API。

## 术语与贡献

用户术语和系统术语共同引用 [`glossary/concepts.json`](../glossary/concepts.json)。新增或改名时维护这份机器概念源并复用稳定 `concept_id`，不要另建术语映射。

参与贡献前先查找现有 Issue，并确认范围、验收和文件所有权。共享核心、schema、授权、公共 API、依赖锁、CI 和 `AGENTS.md` 由维护者串行整合。使用合成、小型 fixture；不要提交真实合同、生产快照、密钥、运行日志或个人信息。普通 PR 按受影响范围运行检查，说明源码 SHA、命令、结果和未运行项。完整候选验收须针对固定 SHA 执行，不能拼接不同 SHA 的局部结果。

提交 PR 不保证被接受；维护者可以要求修改或拒绝。仅在 Issue 全部验收完成时使用 `Closes #N`，部分关联使用 `Refs #N`。保留第三方许可和署名，不要将第三方数据或依赖重新标为项目材料。
