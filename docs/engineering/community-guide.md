# 用户上手与扩展指南

本指南说明如何完成一次案件审查、如何理解现有规则包和只读连接器的扩展边界，以及如何参与上游贡献。实际入口和权限以部署配置、当前账号及服务端返回为准。

- 第一次开发环境启动见[本地开发](local-development.md)。
- 产品能力与边界见[能力与边界](../product/capabilities.md)和[案件审查工作流](../product/workflow.md)。
- 贡献流程见[贡献与协作](contributing.md)，许可信息见[许可与贡献](licensing.md)和仓库根目录 [`LICENSE`](https://github.com/Rupert-WLLP-Bai/contract-audit-workbench/blob/main/LICENSE)。

## 当前源码与可用入口

左侧主导航提供五个入口，实际可见内容以部署版本和当前账号权限为准：

- “工作台”：合同审查、审查任务、整改中心、报告中心、证据中心、补证时效。
- “案件”：案件管理，以及案件支援访问、版本对照。
- “合同台账”：合同登记列表，以及合同会签、主体台账。
- “知识与规则”：规则包治理、模板管理。
- “Agent Studio”：执行工作区。

另有组织与权限、工具网关、系统设置、系统健康、审计日志、使用手册和 API 文档等次级入口；具体可见页面随当前部署与角色权限变化。数据库兼容范围以当前源码 [`internal/store/migrations.go`](../../internal/store/migrations.go) 和迁移目录为准。应用启动会核对迁移账本，不自动执行迁移；多服务部署使用独立迁移作业和各自数据库身份，详见[部署模式](../operations/deployment.md)。源码和代码检查不证明目标环境已配置或部署验收完成。

本地受支持的入口见[本地开发](local-development.md)：先运行 `make setup`、`make app-bootstrap`、`make app-config`、`make infra-up` 和 `make infra-smoke`，再使用 `make apps-up` 配置真实模型网关，或使用仅供开发/测试的 `make apps-up-fixture`。单进程开发使用 `make dev` 与 `make web`。

租户身份、工作上下文、配置、实时发送控制、运营快照和生命周期操作已有源码与契约。具体环境仍须由授权管理员配置并验证。本指南说明代码中的入口，不构成非开发者试用、外部专业复核、部署或完整业务验收。可信回执、本地历史与来源观察记录不表示银行、finance 或 ERP 系统已经连接。

## 从工作台完成一次案件审查

以下步骤适用于已有相应账号和案件权限的用户。演示账号只用于本机开发和测试环境。

1. 从左侧“案件”进入案件管理，打开已有案件，或由有创建权限的账号选择“新建案件”。填写标题，并选择适用的业务线、场景和合同类型。案件身份和授权范围由服务端确定；不要自行构造租户、组织或案件编号。
2. 在案件详情的“材料与版本”中上传获准使用的材料，选择材料角色并等待解析。若旧材料选择待确认，先按服务端清单确认；新材料不会自动改写或加入已经开始的审查。
3. 打开“审查记录”，查看“审查准备清单”。核对业务分类、所需材料和解析状态、规则包、法律或制度依据，以及必要的业务时间。状态未知、权限不足或依赖未满足时先停下，按页面入口补齐或联系案件管理员。
4. 选择“单合同预审”或“完整审查”。单合同预审只覆盖清单明确列出的有限检查；当前预审范围不能替代跨材料对照、正式制度/法律依据审查或其他完整审查要求。完整审查也须核对当前案件的适用范围和所需依据。
5. 准备就绪后由有权人员开始审查。服务端受理时重新检查授权和材料，并冻结本次输入、解析、规则与知识版本。之后的材料或配置变化不会改写旧尝试；要核对新事实时发起新审查。
6. 在审查工作区的“原文核对”中逐项核对引用与冻结原文。可用“关键条款导航”定位已保存条款或正文片段；分类和片段不等于完整条款或风险判断。原文位置、材料版本或摘要不一致时停止确认。
7. 在“人工办理”记录有依据的人工判断。模型输出只是建议；引用无法核验时不要确认。需要整改时从案件“协作与归档”中的“整改与复核”或工作台“整改中心”进入，关联准确来源尝试并在整改后发起新审查。通过案件“审查报告与归档”或工作台“报告中心”查看/生成绑定所选审查记录的报告。历史判断和报告不会被新运行覆盖。

只读账号不能代替经办人上传材料或代替审查员保存决定。跨组织、跨租户案件访问须由服务端正式授权；浏览器显示的名称、链接或导出文件本身不构成授权。角色无法执行当前动作时，请联系案件管理员核对成员关系和案件范围，不要修改请求字段。

## 未完成办理与权限变化

首页“我的未完成办理”由服务端按当前身份、租户、工作区和案件权限分页返回。换浏览器或重新登录后可从列表找回；每次继续上传时服务端都会重新核对当前授权、案件是否可写及原文件身份。按提示选择同一原文件，文件名、大小或 SHA-256 不匹配时停止续办。当前账号无权继续时，使用有权身份登录，或请案件管理员核实权限；不要借用他人的续办标识。

审查准备期间主动取消且输入尚未冻结时，可回案件页重新查看准备清单并按服务端提供的动作发起。已冻结输入应按原审查的冻结上下文处理；授权变化或状态无法确认时先联系管理员。未知状态不是通过，也不是失败事实，不要绕过检查继续办理。

## 多租户用户与运营操作

租户与组织是服务端解析的身份和隔离范围，成员关系、角色和工作上下文不能靠更改 URL 或请求字段获得。遇到权限、上下文或授权未知时，先刷新并核实当前身份；仍无法确认时停止操作并联系管理员。身份导入、案件只读支援、租户运营、预算与恢复流程统一见[多租户身份与运营支持](../operations/multi-company-operations.md)及其[术语源](../glossary/concepts.json)，本指南不另维护一套多租户操作规程。

### 常见提示

| 界面提示 | 处理方式 |
| --- | --- |
| 当前账号没有发起审查权限 | 请由具备权限的经办人、审查员或管理员处理；不要修改客户端身份或请求字段。 |
| 材料集合待确认或解析失败 | 按准备清单检查材料、解析状态和本次选择；失败材料仍保留在案件中，不代表风险为零。 |
| 无法确认是否可以开始审查 | 刷新服务端准备清单。状态仍未知时联系管理员，不要把未知当作可执行。 |
| 请修正以下字段 | 在规则包编辑页按字段提示修改草稿，再运行服务端校验。 |
| 本次运行没有形成风险线索 | 这不等于合同无风险，也不代替人工复核。 |
| 登录、材料读取或保存失败 | 记录案件编号和页面错误并联系管理员。不要在公开 Issue、截图或日志中附合同原文、凭据或个人信息。 |
| 当前会话或上下文已变化 | 重新登录或刷新页面，核对当前租户和组织，再重新提交；不要重放旧请求。 |
| 当前身份未获平台租户控制授权 | 请平台管理员核对精确 actor ID 与 Core 数据库 login 双白名单。租户管理员权限不会自动获得平台运营权。 |
| 租户操作当前状态或前置条件不允许此步骤 | 保留 operation ID 和 revision，先核对当前状态及已完成步骤，再联系授权平台运营者续办。 |
| 暂时无法读取预算上限或余量 | 保持未知；暂停需要精确预算判断的调用，并由管理员核对模型网关与服务端账本。 |

## 现有扩展方式

### 规则包

有对应管理权限的管理员可在“规则包治理”创建草稿、填写规则范围和依据并运行服务端校验。若清单包含 fixture suite，再运行对应用例，然后按治理步骤批准并发布。页面只接受当前会话所属的可信租户；输入中的 tenant ID 不是授权来源。

规则阈值使用十进制或规范有理数表示，避免浮点舍入。每条规则应声明业务范围、比较器、事实维度、材料角色、单位、所需对象和依据来源。样例 [`author-demo.json`](../../internal/rulepack/testdata/author-demo.json) 是合成数据，只用于理解 `rulepack/v1` 字段，不是合同或政策依据。

发布后，审查受理会冻结规则包版本和摘要。修改已发布规则应建立新版本；不得覆盖旧审查或伪造旧版本批准。校验失败时按页面字段提示修正后再提交。

### 能力包

Capability pack 是受限 JSON 清单，声明业务场景、材料角色、精确 RulePack 版本、能力和比较器引用、显示字段及 fixture 标识。主机只接受预先登记的 capability、connector 和 comparator；未知引用、重复版本或不支持的 host contract 会被拒绝。

服务从源码嵌入已审查清单并与主机白名单比对。系统不提供用户上传 ZIP、网络安装包、运行包内脚本或 SQL、第三方动态插件发现，或任意比较器。新增能力清单需提交上游评审，并同时核对主机实现、白名单、fixture 和授权边界；只添加 JSON 不代表功能已经上线。

### 外部只读连接器

Go 接口合同见 [`internal/auditext/types.go`](../../internal/auditext/types.go)。`ReadConnector` 只提供 `ID()` 和 `Read(context.Context, ReadRequest) (Observation, error)`。服务端构造授权范围、映射和对象标识；调用方不能提供任意 URL、HTTP 方法、请求头或凭据。Observation 应带版本、时间范围、可用性和证据字段。外部快照证据与合同原文引用是不同类型。

该接口位于 Go `internal/` 路径，不是独立 Go module 可导入的稳定 SDK。连接器由宿主服务实现，部署方固定 endpoint、凭据、白名单、超时和响应大小。工具与外部业务读取保持只读；新增连接器不能增加外部写回、自动审批、签署或付款。源码接口不表示某个外部系统已接通；现有来源观察、历史和可信回执仍按各自能力使用，不据此承诺真实 finance/ERP 系统集成。

### HTTP API 与类型变更

HTTP 契约以 Go 中的类型与路由声明为源。`make generate-openapi` 先运行 Go OpenAPI 生成器，再生成前端 TypeScript wire 类型；`make check-openapi-generated` 检查两者是否与源码一致。新增或修改路由、DTO、状态或错误码时，先更新 Go 契约，再运行生成与受影响检查。不要手改 `internal/apidocs/openapi.json` 或 `web/src/api/wire.generated.ts`，也不要把数据库字段名当作外部 API。

## 术语与贡献

用户术语和系统术语共同引用 [`glossary/concepts.json`](../glossary/concepts.json)。新增或改名时维护这份机器概念源并复用稳定 `concept_id`，不要另建术语映射。

参与贡献前先查找现有 Issue，并确认范围、验收和文件所有权。共享核心、schema、授权、公共 API、依赖锁、CI 和 `AGENTS.md` 由维护者串行整合。使用合成、小型 fixture；不要提交真实合同、生产快照、密钥、运行日志或个人信息。普通 PR 按受影响范围运行检查，说明源码 SHA、命令、结果和未运行项。完整候选验收须针对固定 SHA 执行，不能拼接不同 SHA 的局部结果。

提交 PR 不保证被接受；维护者可以要求修改或拒绝。仅在 Issue 全部验收完成时使用 `Closes #N`，部分关联使用 `Refs #N`。保留第三方许可和署名，不要将第三方数据或依赖重新标为项目材料。

## 许可与分发

许可状态、适用范围和分发条件以根目录 [`LICENSE`](https://github.com/Rupert-WLLP-Bai/contract-audit-workbench/blob/main/LICENSE) 及专门许可 Issue 的结论为准；不要仅据文件日期声称许可已生效或属于 OSI 开源许可。第三方材料仍适用各自条款；不要提交无权提供的素材、真实合同或数据。
