# 能力与边界

合同审计工作台用来组织案件材料、跑规则核对、给出带原文引用的模型建议，并记录人工复核、整改和报告。模型结果是建议，请对照本次审查的原文再确认。

## 已有工作流能力

- 材料解析、案件准备清单和基于当前服务器状态的下一步提示；审查范围可选完整审查或适用时的单合同预审。
- 制度按租户、制度标识和版本区分；知识可指定版本读取并保留版本链接。审查按业务时间、租户、案件权限和规则包版本选择适用知识，冻结本次使用版本及摘要；更新或撤回不会改写旧尝试。可支持的制度数值要求须能从原文提取并与规则包一致，无法核实时保留待补充事项。
- 材料引用保留跨行否定词和限制条件，并记录本次审查原文位置；经核验的引用能打开冻结原文并按 Unicode 码点高亮，展示材料版本、正文及解析摘要。关键条款导航帮助定位已保存条款或片段，不表示风险已判定。缺少身份、摘要或精确原文校验时拒绝定位。
- 人工决定、整改和复核保留历史，不覆盖旧审查记录。
- 文档上传、重新解析和审查提交会校验角色与案件权限；异步任务由 PostgreSQL 状态驱动。
- 合同草稿、台账、冻结修订、历史来源导入与顺序会签；付款、履约和资产事实按当前权限分别记录。

## 合同事实、来源与版本边界

合同台账区分草稿、冻结修订、历史导入、会签、签署和履约事实。冻结修订不会被后续草稿编辑覆盖；每次案件审查也冻结当次材料、解析、规则与知识版本。存量来源、会签历史或外部事实没有证据时保持未知，不从当前配置补造历史。

付款资格核验、可信付款/冲正回执、冻结资产计划、人工移交及可信 ERP 入账/冲正是工作台已有的业务记录。它们按当前授权流程写入本地事实，不表示银行已转账、金融或 ERP 来源已实时连接，也不执行外部系统写回。既有来源身份、观察历史及可信回执能力继续按其原始边界使用；当前文档不承诺真实外部系统接入。

数据库迁移兼容范围以当前源码的 [`internal/store/migrations.go`](../../internal/store/migrations.go) 和迁移目录为准；应用打开连接时核对迁移账本，不自动执行迁移（[`internal/store/pg.go`](../../internal/store/pg.go)）。源码存在某项功能，不证明目标环境已升级、已配置或完成完整候选验收。PR [#144](https://github.com/Rupert-WLLP-Bai/contract-audit-workbench/pull/144) 合入源码 `1a9eae0` 时的历史局部 `pr-fast-gate` 证据见[原运行记录](https://github.com/Rupert-WLLP-Bai/contract-audit-workbench/actions/runs/41339271202)；它只对应当时固定源码，不代表当前源码、当前部署或完整验收结果。

会签记录中的审批决定、任务材料白名单与转交有现存代码模型。它们不能被描述为外部电子签名、真实签署或履约完成凭证。已签存量导入需要保留来源；历史会签未知时不会伪造签名或会签轮次。当前源码通过 `CLM_ENVELOPE_KEYS` 中按租户与用途配置的版本化密钥保护受限供应方字段；`CLM_DATA_KEY` 单独设置不会配置当前版本化读写。未配置所需 envelope keys 时，相关受限字段写入失败关闭，不落明文；旧 `clmv1:` 读取还需要显式 legacy key ref。该配置不复用 `LLM_CONFIG_KEY`。密钥格式与部署入口见[部署模式](../operations/deployment.md)。

## 数据与权限边界

案件访问由服务端按租户、组织和角色判断。材料、解析和规则按每次审查冻结。工具网关只读；写回外部系统需要人工授权。检索排名不能当作风险高低。

## 工作台辅助页面

健康页按分组显示服务状态和连接说明。版本对照页并排查看各次审查的原文。审查工作区可按时间线或事件树查看已保存事件。

更多用户路径见[案件审查工作流](workflow.md)，架构边界见[架构概览](../architecture/overview.md)。
