# 案件审查工作流

## 从工作台开始

左侧主导航的“案件”用于打开案件管理。选择已有案件，或在有创建权限时选择“新建案件”；案件范围、成员和下一步动作由服务端按当前身份决定。不要通过改 URL、租户编号或请求字段扩大权限。

案件详情页提供“案件概览”“材料与版本”“审查记录”“主体与对象”“适用依据”“协作与归档”分区。初次办理可按这条路径进行：

1. 在“材料与版本”上传获准用于本案的材料，选择材料角色并等待解析。若系统要求确认旧材料集合，先按页面提示确认；不能从文件名或模型结果推断材料角色。
2. 打开“审查记录”中的“审查准备清单”，核对登记业务分类、业务时间、材料版本和解析状态、所选规则包、所需材料及适用依据。缺项按页面提供的入口处理；身份、权限或状态未知时先联系案件管理员。
3. 选择本次审查范围。只有主合同固定付款比例等有限检查时，可选“单合同预审”；它不包含完整跨材料对照或正式制度、法律依据审查。更完整的合同审查选择“完整审查”，并核对所需材料、已发布规则包及适用依据。以清单当前列出的检查和缺项为准。
4. 准备就绪后，由有权人员开始审查。服务端受理时会重新校验身份、范围和材料，并冻结本次使用的输入。新增材料、更新规则或更正主体不会改写既有尝试；需要复核变更时发起新审查。
5. 进入审查工作区后，在“原文核对”中检查引用对应的冻结材料和具体位置。需要定位已保存条款时可用“关键条款导航”；分类和关键词只帮助查找，不代表风险判断。原文、摘要或定位无法核实的内容保持待核对。
6. 在“人工办理”中记录有依据的人工判断。模型结果只是建议；未能对上冻结原文的引用不能变成已确认结论。人工决定追加保存，不覆盖旧判断。
7. 需要整改时，在案件的“协作与归档”分区打开“整改与复核”，或从工作台的“整改中心”进入。整改复核应关联准确的来源尝试；完成整改后发起新审查核对结果。报告在案件的“审查报告与归档”或工作台“报告中心”查看/生成，并绑定所选择的审查记录。

左侧主导航也提供“工作台”“合同台账”“知识与规则”和“Agent Studio”。合同台账中的合同草稿、版本与会签属于合同办理流程，和案件审查中的人工决定分开保存；具体入口和操作权限见下节及[能力与边界](capabilities.md)。

## 准备、受理与冻结

有服务对象的案件需要业务时间。普通旧案件没有服务对象时可以省略；需要填写时按北京时间输入，浏览器时区不会改变提交时点。审查尝试会冻结服务对象、已确认合同关联及映射版本；即使没有启用治理规则包也保留对象上下文。重试校验冻结上下文；发生变化时重新发起审查，原尝试保留原输入和解析记录。

审查在准备期间由用户主动取消且尚未冻结输入时，返回案件页核对准备清单和审查范围；准备就绪后，有权人员可选择“重新发起新审查”。新审查按当前材料和依据受理，原取消记录与原件保留。如果输入已经冻结，请在原审查中核对能否按冻结输入重新执行；取消原因不明或授权发生变化时，请先联系案件管理员。

提交后未收到结果或重新登录时，请先核对当前租户和发起审查时的组织，再查看案件中的已受理记录。同一请求在当前权限允许且发起组织可核实的情况下返回原受理结果；较早记录的发起组织无法核实或系统提示无法重放时，请先查看已有记录，再决定下一步。

### 输入按次冻结

审查尝试保存其使用的材料、解析内容、规则包和知识版本。之后替换材料或更新知识，不改写旧记录。范围身份未知、规则依赖缺失、材料未解析或权限无法确认时，不要把“未知”当成“通过”，也不要绕过清单提交。

## 原文、人工决定与后续办理

经办人员和审查人员分别看到材料、报告、人工复核等工作重点。结果里的引用须对应冻结原文。报告由服务端检查选择的执行及其冻结规则和完整性条件；生成报告不等于专业复核或外部验收。

单合同预审范围有限：当前主要核对主合同中可识别的固定付款比例表达。比例合计为 100% 不证明条款完整、计算基数相同或合同合规；跨材料比对、正式制度/法律依据及其他风险不在这一预审范围。若需要这些检查，应选择完整审查并按服务端准备清单补齐条件。

整改复核从指定来源尝试的冻结业务时间发起新审查，保留时间精度和原审查范围；中间即使有其他审查，仍按精确来源记录核验。相邻运行差异只是参考，满足服务端来源与复核记录条件后才关闭整改。旧审查、人工判断和已生成报告保持原样。

## 合同台账、来源与会签

左侧“合同台账”打开合同列表（页面面包屑显示“合同登记”）；合同会签从该主入口的“合同会签”次级链接进入。

1. 有相应权限时创建合同草稿，维护内容并保存。冻结版本后，后续编辑不会改写已冻结修订；版本及历史导入来源按各自记录保存。历史会签、签名或外部事实无法确认时保持未知，不补造事实。
2. 打开“合同会签”，查看当前账号的待办、已审批事项和发起的会签。选择一条记录，核对冻结版本和已有意见。
3. 对当前授权下的活动待办，填写审批意见或退回理由，再提交决定。页面只有在服务端确认后更新状态；角色变更、待办转交、合同版本变化或权限变化时，按提示刷新或联系合同管理员。

会签决定与案件中的人工审查意见分别保存。会签记录不是外部电子签名。可操作入口以当前部署和账号权限为准。

## 续办与补件

首页“我的未完成办理”由服务端按当前身份、租户、工作区和案件权限返回。换浏览器或重新登录后，可从列表重新找回办理；每次继续上传都会重新检查当前授权、案件是否可写以及原文件身份。按页面要求选择同一原文件，文件名、大小和 SHA-256 不匹配时停止续办；不要借用他人的续办标识或手改身份信息。无权继续时，使用有权身份登录或请案件管理员核对当前成员关系和案件权限。

此前候选在真实受限 Core 角色下曾出现会话 RLS 和回执失败，历史记录见 #97；#220 的跨会话复现保留在交付目录的 `optimization-review-20261104/issue-220-repro-red.log`。源码 `96e3054` 已修复受限角色跨会话续传及原子回执，隔离 PostgreSQL 18.6 的局部验证为 **PASS**。required gate、目标环境升级及 #97 固定候选完整验收均为 **NOT_RUN**；局部结果不能证明当前部署已升级或交付验收通过。

归档只从个人列表隐藏操作，不删除案件或材料；归档后不接收新的上传重试，已经开始的上传仍可完成。补充材料请求关联案件任务、材料和回执。收到材料后需发起新审查并核对新结果和引用，原执行、人工判断及请求历史保持不变。

## 经验

审查反馈可以引用本次审查原文，作为整理经验的依据。经验经审阅、授权和发布后才能用于适用案件。
