# 案件审查工作流

## 准备与受理

案件页的审查准备清单列出材料版本、解析状态、规则检查和缺失依据，并提供补齐入口。开始动作以服务端清单为准；受理时还会重新校验权限与材料。身份、准备清单或运行状态未知时，界面不会开放写入。

有服务对象的案件需要业务时间。普通旧案件没有服务对象时可以省略；需要填写时按北京时间输入，浏览器时区不会改变提交时点。审查尝试会冻结服务对象、已确认合同关联及映射版本；即使没有启用治理规则包也保留对象上下文。重试校验冻结上下文；发生变化时重新发起审查，原尝试保留原输入和解析记录。

审查在准备期间由用户主动取消且尚未冻结输入时，返回案件页核对准备清单和审查范围；准备就绪后，有权人员可选择“重新发起新审查”。新审查按当前材料和依据受理，原取消记录与原件保留。如果输入已经冻结，请在原审查中核对能否按冻结输入重新执行；取消原因不明或授权发生变化时，请先联系案件管理员。

提交后未收到结果或重新登录时，请先核对当前租户和发起审查时的组织，再查看案件中的已受理记录。同一请求在当前权限允许且发起组织可核实的情况下返回原受理结果；较早记录的发起组织无法核实或系统提示无法重放时，请先查看已有记录，再决定下一步。

## 审查与复核

审查尝试保存其使用的材料、解析内容、规则包和知识版本。之后替换材料或更新知识，不改写旧记录。结果中的引用须与冻结原文和精确位置对应；模型给出的内容只作为建议。

经办人员和审查人员分别看到材料、报告、人工复核等工作重点。报告由服务端检查选择的执行及其冻结规则和完整性条件。整改复核可以从来源尝试的冻结业务时间发起新审查，保留完整时间精度与原审查范围；中间即使有其他审查，仍按精确来源记录核验。相邻运行差异只是参考，符合服务端来源与复核记录条件后才关闭整改。

单合同预审的范围有限：当前只对尝试冻结的主合同识别部分固定付款比例表达。比例合计为 100% 不证明条款完整、基数相同或合同合规；跨材料比对、制度法律依据和其他风险不在此预审范围。范围身份未知时保持待核对。

## 合同登记与会签

1. 打开“合同登记”，选择“新建合同草稿”，填写合同内容并保存。存量合同登记需要保留来源；无法取得的历史会签或签名保持未知。
2. 打开“合同会签”，查看当前账号的待办、已审批事项和发起的会签。选择一条记录，核对冻结版本和已有意见。
3. 对有权处理的活动待办，填写审批意见或退回理由，再选择“通过”或“退回修改”。只有服务端确认后，页面才更新状态。

会签决定与案件中的人工审查意见分别保存。会签记录不等于外部电子签名或实际签署证明；具体可操作入口和权限以当前部署及服务端返回为准。

## 未完成办理与补件

“我的未完成办理”按当前租户和原经办人从 PostgreSQL 分页读取。服务器会保存原请求；换浏览器或重新登录后，原经办人可在当前权限允许时重新选取原文件继续。提交前会检查文件名、大小和 SHA-256；其他成员不能取得原经办人的续办标识。

此前候选在真实受限 Core 角色下曾出现会话 RLS 和回执失败，历史记录见 #97；#220 的跨会话复现保留在交付目录的 `optimization-review-20261104/issue-220-repro-red.log`。源码 `96e3054` 已修复受限角色跨会话续传及原子回执，隔离 PostgreSQL 18.6 的局部验证为 **PASS**。required gate、目标环境升级及 #97 固定候选完整验收均为 **NOT_RUN**；局部结果不能证明当前部署已升级或交付验收通过。

归档只从个人列表隐藏操作，不删除案件或材料；归档后不接收新的上传重试，已经开始的上传仍可完成。补充材料请求关联案件任务、材料和回执。收到材料后需发起新审查并核对新结果和引用，原执行、人工判断及请求历史保持不变。

## 经验

审查反馈可以引用本次审查原文，作为整理经验的依据。经验经审阅、授权和发布后才能用于适用案件；提交反馈不等于自动发布，也不把模型建议变成人工决定。
