# 案件审查工作流

## 准备与受理

案件页的审查准备清单列出材料版本、解析状态、规则检查和缺失依据，并提供补齐入口。开始动作以服务端清单为准；受理时还会重新校验权限与材料。身份、准备清单或运行状态未知时，界面不会开放写入。

有服务对象的案件需要业务时间。普通旧案件没有服务对象时可以省略；需要填写时按北京时间输入，浏览器时区不会改变提交时点。审查尝试会冻结服务对象、已确认合同关联及映射版本；即使没有启用治理规则包也保留对象上下文。重试校验冻结上下文；发生变化时重新发起审查，原尝试保留原输入和解析记录。

## 审查与复核

审查尝试保存其使用的材料、解析内容、规则包和知识版本。之后替换材料或更新知识，不改写旧记录。结果中的引用须与冻结原文和精确位置对应；模型给出的内容只作为建议。

经办人员和审查人员分别看到材料、报告、人工复核等工作重点。报告由服务端检查选择的执行及其冻结规则和完整性条件。整改复核可以从来源尝试的冻结业务时间发起新审查，保留完整时间精度与原审查范围；中间即使有其他审查，仍按精确来源记录核验。相邻运行差异只是参考，符合服务端来源与复核记录条件后才关闭整改。

单合同预审的范围有限：当前只对尝试冻结的主合同识别部分固定付款比例表达。比例合计为 100% 不证明条款完整、基数相同或合同合规；跨材料比对、制度法律依据和其他风险不在此预审范围。范围身份未知时保持待核对。

## 未完成办理与补件

“我的未完成办理”按当前租户和原经办人从 PostgreSQL 分页读取。换浏览器或重新登录后，用户可重新选取原文件续传到同一案件；提交前检查文件名、大小和 SHA-256，并复用服务器保存的原请求。其他成员不能取得原经办人的续办标识。

归档只从个人列表隐藏操作，不删除案件或材料；归档后不接收新的上传重试，已经开始的上传仍可完成。补充材料请求关联案件任务、材料和回执。收到材料后需发起新审查并核对新结果和引用，原执行、人工判断及请求历史保持不变。

## 经验

审查反馈可以引用本次审查原文，作为整理经验的依据。经验经审阅、授权和发布后才能用于适用案件；提交反馈不等于自动发布，也不把模型建议变成人工决定。
